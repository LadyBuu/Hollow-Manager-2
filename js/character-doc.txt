1. OVERVIEW
================================================================================

The Character Module is a comprehensive system for managing characters in the
Hollow Blades application. It handles character CRUD operations, statistics,
magic, classes, eliminations, and social relationships through a modular
architecture with clear separation of concerns.

Key Principles:
- Single Responsibility: Each module has one clear job
- Separation of Concerns: Rendering, events, and data are separate
- Immutable Getters: Query functions never mutate data
- Explicit Mutations: All state changes follow a consistent pattern
- XSS Prevention: All user data is escaped or inserted via textContent
- Candidate-Based Commits: Mutations validate before applying

15. MUTATION CONTRACT
================================================================================

All mutation functions follow this pattern:

VALIDATE INPUT
    - Validate all parameters
    - Validate domain rules
    - No mutation occurs during validation

SNAPSHOT
    - Create backup using createSafeBackup()
    - Abort if backup fails

MUTATE
    - Apply changes to window.data
    - Normalise data structures if needed

LOG
    - Record activity via logActivity()
    - Failure-safe: wrapped in try/catch
    - Does NOT trigger rollback

SAVE
    - Persist via saveData()
    - Wrapped in Promise.resolve().then() to catch sync exceptions

UI COMMIT
    - Refresh UI from restored state
    - Show success notification

ROLLBACK (on failure)
    - Restore window.data from backup
    - Refresh UI from restored state
    - Show error notification

Return Value:
- All mutation functions return Promise<boolean>
- true = success, false = failure


================================================================================
16. SECURITY CONTRACT
================================================================================

XSS PREVENTION:
- All user-controlled data inserted via DOM APIs (textContent, value)
- No user data interpolated into HTML strings
- Dynamic CSS values pass through whitelist/validation
- All IDs inserted via dataset, not HTML attributes

DATA VALIDATION:
- All inputs validated before mutation
- Malformed persisted data handled defensively
- Arrays/objects checked before iteration
- Invalid data fails closed (does not proceed)

ROLLBACK:
- Backup created before every mutation
- On failure, window.data restored from backup
- UI refreshed from restored state

PERSISTENCE:
- All mutations call saveData()
- saveData() provides atomic persistence
- Persistence failures trigger rollback

STATE OWNERSHIP:
- window.data: Source of truth for persisted data
- AppState: Source of truth for UI/edit state
- getCurrentEditId/setCurrentEditId: Canonical selection state
- DOM: Temporary source of form input during save

DEPENDENCY OWNERSHIP:
- Required dependencies: Module cannot function without these
- Feature dependencies: Module degrades gracefully without these
- Optional dependencies: Enhancements that are not required
