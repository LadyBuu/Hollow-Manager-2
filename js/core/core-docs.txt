## System Overview

The HollowBlades core system is a modular JavaScript application architecture built around:

- **IndexedDB persistence** with automatic migrations
- **Centralized state management** (UI state separate from domain data)
- **Transactional mutation pipeline** with automatic rollback
- **Tab-based navigation** with lifecycle management
- **Pure utility functions** for domain operations

### Core Principles

1. **Single Source of Truth**: `window.data` holds all persistent domain data
2. **Separation of Concerns**: UI state (`AppState`) vs Domain data (`window.data`)
3. **Immutability During Transactions**: Backups before mutations, rollback on failure
4. **Coalescing Saves**: Multiple save requests are batched efficiently
5. **Fail-Fast Validation**: All mutations validate before execution

#### Save Queue Semantics

- Multiple save requests while one is in progress are **coalesced**
- Waiters are **frozen** at the start of each save operation
- All waiters in a batch share the result of that save
- New waiters arriving during a save belong to the **next** save
- Prevents "saved successfully" responses for unsaved data

#### Events

| Event | Detail | Description |
|-------|--------|-------------|
| `dataReady` | `{ data, status, error }` | Dispatched when data loads |
| `dataSaveFailed` | `{ error }` | Dispatched when save fails |

### Mutation Utilities Module
**Path:** `js/modules/shared/mutation-utils.js`

Centralized mutation pipeline with validation, snapshot, mutation, persistence, logging, and UI commit.

#### Mutation Pipeline

```
VALIDATE → SNAPSHOT → MUTATE → PERSIST → LOG → UI COMMIT
    │          │         │         │        │       │
    │          │         │         │        │       └── onSuccess callback
    │          │         │         │        └────────── Activity logging
    │          │         │         └─────────────────── saveData() with coalescing
    │          │         └───────────────────────────── mutate(data, backup)
    │          └─────────────────────────────────────── createSafeBackup(data)
    └─────────────────────────────────────────────────── config.validate()
```

#### Key Functions

| Function | Parameters | Returns | Description |
|----------|------------|---------|-------------|
| `performMutation(config)` | `config: Object` | `Promise<Result>` | Complete mutation pipeline |
| `createSafeBackup(data)` | `data: Object` | `Object\|null` | Deep clone with fallbacks |
| `saveWithPromise(options)` | `options: Object` | `Promise<void>` | Wraps saveData() |
| `simpleMutation(logMsg, successMsg, failureMsg, mutateFn, validateFn)` | Various | `Promise<Result>` | Simplified mutation wrapper |
| `refreshUI(options)` | `options: Object` | `void` | Safe UI refresh |

#### Mutation Configuration

```javascript
performMutation({
    // Required
    validate: function() {
        // Returns { valid: true } or { valid: false, message: string }
        return { valid: true };
    },
    mutate: function(data, backup) {
        // Mutates window.data (caller owns this)
        data.characters.push(newCharacter);
    },
    
    // Optional
    getData: function() { return window.data; },  // Override data source
    logMessage: function() { return 'Mutation performed'; }, // Or string
    onSuccess: function(result) { /* UI commit / notification */ },
    onRollback: function(backup) { /* Custom rollback */ },
    onFailure: function(error) { /* Custom failure handling */ },
    skipLog: false,          // Skip activity logging
    skipNotification: false, // Skip notifications
    successMessage: 'Operation completed successfully.',
    failureMessage: 'Operation failed.',
    _testSaveFailure: false  // Force save failure for testing
});

// Returns: Promise<{ success: boolean, data?: any, message?: string }>
```

#### Notification Fallback Chain

1. `window.NotificationSystem.notify()` - Primary
2. `window.showToast()` - Secondary
3. `window.setSession('toast', ...)` + `window.renderToast()` - Tertiary
4. `alert()` - Last resort

### Tab Manager Module
**Path:** `js/core/tab-manager.js`

Centralized tab navigation system. Modules register with TabManager, TabManager calls render functions.

#### Lifecycle

```
1. DOMContentLoaded → TabManager.init()
2. _findTabContentElements() → Find #tab-{name} elements
3. _bindNavLinks() → Bind [data-tab] links
4. _getInitialTab() → From URL hash or DEFAULT_TAB
5. _updateUrlHash() → Update URL
```

## Data Flow

### Load Flow

```
1. database.js loads
   → opens IndexedDB
   → reads data
   → migrates if needed
   → sets window.data

2. loader.js initializes
   → listens for dataReady event
   → when dataReady → marks as ready
   → processes callbacks

3. tab-manager.js initializes
   → checks window.data
   → when data ready → processes initial tab

4. Application modules register with TabManager
   → render when tab is selected
```

### Mutation Flow

```
1. Module calls performMutation(config)

2. Validation phase
   → config.validate() called
   → if invalid → return error

3. Snapshot phase
   → createSafeBackup(data) called
   → if backup fails → return error

4. Mutation phase
   → config.mutate(data, backup) called
   → if error → rollback to backup

5. Persistence phase
   → saveWithPromise() called
   → if save fails → rollback to backup

6. Log phase
   → window.logActivity() called (if not skipped)

7. UI Commit phase
   → config.onSuccess() called (if provided)
   → notification shown (if not skipped)

8. Return result
   → { success: true, data: result, message: msg }
```

### State Update Flow

```
1. User action → Module calls state setter
   → setState('characters', 'filterStatus', 'active')
   → AppState.characters.filterStatus = 'active'

2. Module observes state change
   → Re-renders based on new state

3. No persistence → UI state is ephemeral
   → Page reload → state resets to defaults
```

## Best Practices

### Mutation Usage

```javascript
// ✅ DO: Use performMutation for all state changes
function addCharacter(character) {
    return MutationUtils.performMutation({
        validate: function() {
            if (!character.firstName) {
                return { valid: false, message: 'First name is required.' };
            }
            return { valid: true };
        },
        mutate: function(data) {
            data.characters.push(character);
        },
        logMessage: 'Added character: ' + character.firstName,
        successMessage: 'Character added successfully!'
    });
}

// ❌ DON'T: Mutate window.data directly
function addCharacter(character) {
    window.data.characters.push(character);
    window.saveData(); // This bypasses validation and rollback
}
```

### State Management

```javascript
// ✅ DO: Use state for UI concerns
setState('characters', 'filterStatus', 'active');
setState('teams', 'expandedTeamId', teamId);

// ❌ DON'T: Store UI state in window.data
window.data.uiState = { selectedTab: 'characters' };

// ✅ DO: Use window.data for domain data
window.data.characters = characters;  // Persistent
window.data.teams = teams;            // Persistent

// ❌ DON'T: Use AppState for domain data
AppState.characters = characters;     // Not persistent!
```

### Tab Registration

```javascript
// ✅ DO: Register tab renderers
TabManager.register('characters', function(container) {
    CharacterList.render(container);
});

// ✅ DO: Handle data readiness in renderer
TabManager.register('dashboard', function(container) {
    whenDataReady(function(data) {
        if (data) {
            Dashboard.render(container);
        }
    });
});

// ❌ DON'T: Auto-render on dataReady
document.addEventListener('dataReady', function() {
    // This will render before TabManager is ready
    CharacterList.render();
});
```

### Data Queries

```javascript
// ✅ DO: Use CoreUtils for queries
var students = window.CoreUtils.getStudents();
var team = window.CoreUtils.getTeamById(teamId);
var name = window.CoreUtils.getDisplayName(character);

// ✅ DO: Use pure functions
var age = window.calculateAge(character);
var isEliminated = window.isCharacterEliminated(charId, week);

// ❌ DON'T: Write inline queries with null checks everywhere
var students = (window.data && window.data.characters) 
    ? window.data.characters.filter(c => c.status === 'student')
    : [];
```

### Error Handling

```javascript
// ✅ DO: Handle mutation errors
performMutation(config)
    .then(function(result) {
        if (!result.success) {
            showError(result.message);
            return;
        }
        // Handle success
    })
    .catch(function(error) {
        showError('Unexpected error: ' + error.message);
    });

// ✅ DO: Provide user feedback
performMutation({
    // ...
    onFailure: function(error) {
        showError('Failed to save changes: ' + error.message);
    }
});

// ❌ DON'T: Ignore errors
performMutation(config); // Fire and forget!
```
